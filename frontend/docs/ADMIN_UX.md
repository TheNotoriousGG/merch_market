# Админка Амра Шоп: UX baseline

Статус: утверждено владельцем продукта 20 августа 2026 года.

## Цель первого vertical slice

Дать сотруднику полный проверяемый путь:

```text
категория → черновик товара → варианты/SKU → медиа → публикация → складской остаток
```

Админка живёт в текущем frontend под `/admin`, использует backend-managed OIDC session и не дублирует business rules.

## Навигация и визуальный язык

- отдельный `AdminLayout` с постоянной графитовой боковой панелью;
- разделы: Обзор, Товары, Категории, Коллекции, Склад;
- верхняя панель: название раздела, состояние соединения, переход на витрину и меню сотрудника;
- бело-серая рабочая область, фирменный жёлтый только для активного раздела и главного действия;
- общие tokens Amra, локальные CSS Modules, desktop-first;
- storefront `StoreHeader` в admin layout не используется.

## Роли

- `CATALOG_MANAGER`: каталог, категории, коллекции, варианты, медиа и публикация;
- `WAREHOUSE_MANAGER`: balances, приёмка и сверка;
- `ADMIN`: обе области;
- интерфейс следует permissions сессии, но backend остаётся единственным authorization authority.

## Товары

Список — плотная таблица: изображение, имя/slug, статус, категория, варианты, готовность медиа, дата изменения и действия. Предусмотрены поиск, фильтры, сортировка и пагинация.

Редактор — одна страница с последовательными секциями: информация, цена, продвижение, цвета и размеры, фотографии. Закреплённая панель сохраняет все изменяемые поля и показывает, есть ли несохранённые данные. Уход со страницы с изменениями защищён системным предупреждением.

SKU предлагается из кода товара, цвета и размера. До создания его можно изменить, после создания он immutable; исправление выполняется архивированием варианта и созданием нового.

## Медиа и local S3

- local development использует MinIO как S3-compatible container;
- backend выдаёт presigned upload, browser загружает файл напрямую;
- frontend никогда не получает S3 secret;
- после upload сотрудник задаёт alt, порядок и primary flag и подтверждает привязку;
- неподтверждённые объекты удаляются bounded cleanup job;
- проверяются MIME type, размер и наличие объекта;
- production provider остаётся сменным за S3 port/adapter.

## Публикация

Checklist требует заполненного content, active primary category, хотя бы одного active variant/SKU, обязательных attributes, primary media и отсутствия namespace conflicts. Публикация является отдельным подтверждаемым действием. Кнопка остаётся доступной и при неполной карточке: нажатие перечисляет недостающие данные. Несохранённые изменения также нужно сохранить до публикации.

## Склад

Для SKU показываются `on hand`, `reserved`, `available`. Остаток не редактируется полем: приёмка добавляет физическое количество, установка фактического остатка записывает разницу с обязательной причиной. В приёмке доступны поиск по названию и SKU, редактирование количества, прогноз остатка и сохраняемый в пределах вкладки черновик. Команды используют idempotency и ETag.

## Категории и коллекции

Категории отображаются деревом и поддерживают создание, перемещение в допустимой глубине, порядок и `ACTIVE/HIDDEN`; физического удаления нет. Коллекция управляет editorial membership/order, но не ценой или скидкой.

## Ошибки и concurrency

- `401`: предложение войти;
- `403`: недостаточная permission, verified email или MFA;
- validation violations привязываются к полям;
- `412`: автоматическая перезапись запрещена, предлагается загрузить актуальную версию;
- destructive/lifecycle действия требуют подтверждения;
- notification об успехе компактное и не скрывает рабочий контекст;
- trace ID доступен в диагностике ошибки.

## Первый acceptance gate

Local manager входит через Keycloak, создаёт категорию и товар, добавляет вариант и изображение через MinIO, публикует товар; warehouse manager принимает остаток; товар появляется на витрине и availability возвращает `IN_STOCK`.
