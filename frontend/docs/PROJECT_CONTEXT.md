# Контекст продукта: Амра Шоп

Обновлено: 12 сентября 2026 года.

## Замысел

Амра Шоп — интернет-магазин одежды, аксессуаров и лимитированных коллекций бренда Амра. Цель текущего этапа — цельный интерактивный десктопный прототип с наполненной главной страницей, рабочим каталогом и базовыми клиентскими сценариями.

T‑Shop служит ориентиром по удобству каталога, плотности контента и коммерческим блокам. Визуально сайт должен оставаться самостоятельным.

## Утверждённый визуальный язык

- Палитра: графитовый/чёрный, белый, фирменный жёлтый; дополнительные пастельные фоны у товаров.
- Типографика: чистая геометричная, с крупными заголовками и спокойным служебным текстом.
- Формы: большие скругления, модульные карточки, собранные панели.
- Управление: единый стиль чёрно‑жёлтых стрелок и кнопок.
- Хедер: плавающая тёмная капсула; логотип «амра шоп» слева, навигация и иконки справа.
- Порядок навигации: `Новинки → Товары недели → Коллекции → Sale → Покупателям`.
- Иконки поиска, избранного, кабинета и корзины — без текстовых подписей, в единой стилистике.
- Мегабар: компактная центральная панель с карточками категорий и фирменными пиктограммами; категории раскрываются в отдельной панели.
- Карточки товара: компактные в списках; подробности открываются только после клика.
- Футер: модульный, с полезной информацией.

## Реализовано

### Главная

- рекламный слайдер без наложения на следующий блок;
- мегабар и закрывающаяся по клику вне области панель категорий;
- блоки «Новинки», «Товары недели», «Коллекции», Sale и информационные/рекламные модули;
- листание карточек в «Товарах недели» и Sale;
- единый стиль стрелок на всей странице;
- модульный футер.

### Каталог и товары

- маршруты категорий и фильтрация по секции через query-параметр;
- адаптивное по ширине количество компактных карточек;
- пагинация без кнопки «Показать ещё»;
- подробное модальное окно товара с описанием, характеристиками и размерами;
- товарные карточки кликабельны во всех основных подборках;
- первый клик по кнопке товара добавляет его в корзину;
- после добавления кнопка показывает `В корзине · N` и ведёт в корзину вместо повторного добавления;
- избранное и счётчики работают через общее состояние.

### Клиентские разделы

- `/favorites` — избранные товары;
- `/cart` — состав заказа, изменение количества, удаление и итоговая сумма;
- `/checkout` — контактные данные, адрес, повторная проверка корзины и подтверждение заказа;
- `/account` — демонстрационные данные клиента, заказы и история покупок;
- `/privacy` и `/offer` — информационные страницы;
- внешний вид хедера сохраняется на внутренних страницах.

## Важные ограничения текущей версии

- Catalog и storefront banners читаются через синхронизированный generated OpenAPI client; административные transport-вызовы переводятся на него по мере развития контрактов.
- Playwright Chromium покрывает витрину, поиск, клиентскую навигацию, восстановление корзины, checkout и доступ catalog manager к категориям.

- Storefront ещё использует fixture-данные для части секций, но главный баннер и административная поверхность подключены к backend API; баннеры редактируются сотрудником, а изображения хранятся в S3-compatible storage.
- Полный локальный стек собирается единым Compose-проектом `amra-merch-market` без локальных Node или Java.
- Каталог и профиль используют демонстрационные данные в коде.
- Корзина и избранное хранятся в backend и восстанавливаются по guest-cookie или сессии клиента.
- Выбранный размер пока не сохраняется как отдельная характеристика позиции корзины.
- Checkout создаёт неизменяемый снимок подтверждённого заказа, атомарно списывает зарезервированный остаток и очищает корзину.
- Реальная оплата, доставка, возвраты и административное управление заказами ещё не подключены.
- Полноценная мобильная версия запланирована позже.

## Принятое решение о бэкенде

- Frontend и backend разделяются с самого начала.
- Frontend-проект и его репозиторий называются `amra-merch-market-frontend`.
- Backend-проект реализован в отдельном репозитории `amra-merch-market-backend`.
- Текущий репозиторий остаётся только витриной и клиентским приложением.
- Связь между ними строится через версионируемый HTTP API и документированный контракт.
- Backend использует Java 25, Spring Boot, PostgreSQL, OpenAPI-first и Keycloak/OIDC. Production storage и реальные payment/delivery providers остаются отложенными решениями.

## Следующие логичные этапы

1. Провести согласованный аудит ошибок и неровностей на всех маршрутах.
2. Реализовать поиск и состояние результатов.
3. Подключить generated API client и последовательно заменить fixtures готовыми backend contracts.
4. Определить модель варианта товара: размер, цвет, артикул и остаток.
5. Подготовить мобильную версию после завершения десктопного интерфейса.
6. Перед публикацией добавить корректные социальные превью и финально проверить метаданные.

Этот список — ориентир, а не автоматическое разрешение на реализацию. Конкретный следующий этап выбирает пользователь.
